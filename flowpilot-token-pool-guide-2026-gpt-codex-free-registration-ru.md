## Что такое FlowPilot

FlowPilot это Chrome-расширение с боковой панелью от QLHazyCoder:
[https://github.com/QLHazyCoder/FlowPilot](https://github.com/QLHazyCoder/FlowPilot)

По README проекта, FlowPilot предназначен для работы с регистрацией ChatGPT / OpenAI аккаунтов, кодами подтверждения, OAuth, Plus-сценариями, импортом аккаунтов, повторными попытками и историей запусков. Это не просто маленький скрипт с одной кнопкой. Скорее это рабочая панель для онбординга аккаунтов.

Сейчас проект покрывает такие задачи:

- регистрация и OAuth для ChatGPT / OpenAI
- источники CPA, SUB2API и Codex2API
- отдельный flow для Kiro
- email-коды, login-коды и коды привязки почты
- Hotmail, 2925, QQ Mail, 163 Mail, iCloud, Cloud Mail и другие почтовые варианты
- Cloudflare Temp Email, собственные email-пулы и mailbox service pools
- SMS-верификация через сторонние платформы
- IP Proxy модуль, retry, ограничения диапазона выполнения и панель записей аккаунтов

Проще говоря, FlowPilot помогает подготовить аккаунт, пройти авторизацию и записать результат в вашу систему управления аккаунтами.

## Кому это нужно

Такая схема подходит, если вы:

- собираете приватный gateway для GPT или Codex
- управляете несколькими OpenAI / ChatGPT аккаунтами
- тестируете Codex CLI, Claude Code или OpenAI-compatible клиентов
- хотите меньше вручную копировать OAuth callback и коды подтверждения
- хотите понимать, почему конкретный аккаунт упал

Она не очень нужна, если вы:

- используете только один личный ChatGPT аккаунт
- не хотите обслуживать VPS, proxy, mailbox и gateway
- ждёте от инструмента обхода правил платформы
- не готовы к рискам блокировок, failed verification и проблемам оплаты

Для лёгкого личного использования официальный аккаунт проще. FlowPilot имеет смысл тогда, когда у вас уже есть операционная задача: несколько легальных аккаунтов, разные группы, ключи, статусы и журналы ошибок.

## Сначала о правилах

Пул аккаунтов можно использовать нормально, а можно быстро превратить его в источник проблем.

Нормальный сценарий: у вас есть свои аккаунты, командные аккаунты, тестовые аккаунты или оплаченные подписки. Вы хотите видеть, где какой email, какой телефон использовался, в какую группу попал аккаунт и какой клиент через него работает.

Плохой сценарий: массовая бесплатная регистрация, перепродажа непонятных аккаунтов, spam или попытки обойти ограничения платформ. У OpenAI, ChatGPT, Codex, Kiro, PayPal, Google и других сервисов есть свои правила.

Эта статья не объясняет, как обходить антифрод или злоупотреблять бесплатной регистрацией. Здесь только инфраструктура, подготовка, диагностика и аккуратное управление аккаунтами.

## Рекомендуемая архитектура

Практичная схема выглядит так:

```text
Легальные upstream GPT / Codex аккаунты
        ↓
FlowPilot: регистрация, коды, OAuth, запись в панель
        ↓
Sub2API / CPA / SUB2API / Codex2API: аккаунты и API keys
        ↓
Ваши клиенты: Codex CLI, Claude Code, OpenAI-compatible apps
```

Каждый слой решает свою задачу.

FlowPilot работает с браузерным процессом. Gateway хранит аккаунты, группы, API keys, лимиты, логи и статусы. Email-слой принимает коды. HeroSMS закрывает SMS-верификацию, если платформа просит номер телефона.

Так проще искать проблему. Нет письма, проверяете mailbox. Нет SMS, проверяете страну, сервис и баланс. Не проходит OAuth, смотрите callback и URL панели. Запросы возвращают 401, проверяете состояние импортированного аккаунта.

## Установка FlowPilot

Официальный README описывает базовый путь так:

1. Открыть `chrome://extensions/`.
2. Включить developer mode.
3. Нажать "Load unpacked".
4. Выбрать директорию проекта FlowPilot.
5. Открыть боковую панель расширения.
6. Выбрать flow и источник.
7. Заполнить mailbox, verification, Plus payment или platform parameters.
8. Сначала пройти несколько шагов вручную, и только потом использовать Auto.

Не спешите. Часть ошибок выглядит как проблема FlowPilot, но на деле это неверный Temp API, неправильный Admin Auth, неверный URL админки gateway, proxy не применился или на SMS-сервисе нет баланса.

## Как выбрать source: SUB2API, CPA, Codex2API или Kiro

FlowPilot поддерживает несколько источников.

### SUB2API

SUB2API подходит, если аккаунты должны попасть в Sub2API gateway. Вы указываете адрес админки, логин, пароль, группу и при необходимости proxy. После OAuth аккаунт записывается в gateway и дальше используется через ваши API keys.

Для Codex CLI, Claude Code и OpenAI-compatible клиентов это обычно самый понятный вариант.

### CPA

CPA нужен для классических OAuth panel workflows. В Plus mode он также может импортировать текущую ChatGPT session в CPA.

### Codex2API

Codex2API сохраняет OAuth-подход и сейчас не поддерживает прямой импорт Plus session. Этот вариант полезен, если ваш стек строится вокруг Codex-доступа.

### Kiro

Kiro имеет отдельный flow. В README упоминаются Builder ID registration, desktop authorization и `kiro.rs` upload path. Его лучше не смешивать с обычными OpenAI Plus или GPT сценариями.

Выбирайте source по месту, куда должен попасть аккаунт. Конечная панель важнее названия режима.

## Email-верификация

FlowPilot поддерживает webmail polling, API mailbox polling и local helper. В материалах проекта упоминаются Hotmail, 2925, QQ Mail, 163 Mail, 126 Mail, iCloud, Cloud Mail, YYDS Mail, Cloudflare Temp Email и custom mailbox pools.

Для автоматизации Cloudflare Temp Email часто удобнее обычных почтовых ящиков. Он может создавать адреса и отдавать письма через API, а FlowPilot может опрашивать коды без постоянного входа в webmail.

Важны три условия:

- почта стабильно принимает письма от GPT / OpenAI / Codex related services
- FlowPilot может получить код
- каждый аккаунт можно связать с конкретным email

Не смешивайте источники почты без нужды. Когда через неделю придётся восстанавливать аккаунт или искать ошибку, хаос в email-источниках будет мешать.

## Proxy и IP-среда

В FlowPilot есть IP Proxy модуль. В официальной документации он описан как способ управлять proxy прямо внутри расширения и видеть текущий proxy, current exit IP и diagnostic status.

Главная мысль простая: стабильность важнее частой смены IP.

Регистрация, OAuth, Plus payment и login verification плохо переносят резкие изменения окружения. Чистый стабильный IP обычно лучше, чем прокси-пул, который меняет выход каждые несколько минут.

Перед Auto проверьте:

- страница в браузере реально идёт через нужный proxy
- регион IP не конфликтует с номером и платёжным окружением
- proxy не отваливается между регистрацией и OAuth callback
- статусная карточка FlowPilot не показывает failure takeover

Если proxy не применился, остановитесь и исправьте это. Иначе вы просто получите больше неудачных записей.

## Первый запуск

Первый запуск должен быть маленьким.

### Шаг 1: проверить gateway

Сначала зайдите в Sub2API, CPA или Codex2API. Убедитесь, что админка открывается, группы созданы, тестовый API key можно выпустить.

### Шаг 2: проверить email-код

Настройте Cloudflare Temp Email или ваш mailbox pool. Пройдите только до шага получения email-кода и убедитесь, что FlowPilot его видит.

### Шаг 3: проверить SMS, если оно нужно

Если платформа просит телефон, сначала закажите номер в HeroSMS вручную. Проверьте сервис и страну.

### Шаг 4: пройти OAuth и write-back

После авторизации проверьте панель gateway. Аккаунт должен появиться в правильной группе и иметь нормальный OAuth status.

### Шаг 5: протестировать реальным клиентом

Отправьте маленький запрос через Codex CLI, Claude Code или OpenAI-compatible client. Расширять пул стоит только после этого.

## Как поддерживать здоровый пул

Здоровый пул это не просто много аккаунтов. Это понятные записи.

Минимально стоит хранить:

| Поле | Зачем нужно |
|---|---|
| Email | Восстановление и история проверок |
| Phone source | Анализ успешности SMS |
| Registration date | Поиск проблем по batch |
| Source | SUB2API, CPA, Codex2API или Kiro |
| Group | Отдельно GPT, Codex и тестовые аккаунты |
| Status | Healthy, pending verification, failed, paused |
| Failure reason | Email, SMS, OAuth, proxy, payment или write-back |

История запусков FlowPilot и local helper уменьшают ручную работу, но периодическая проверка всё равно нужна. Следите за 401, 403, слетевшим логином, истёкшей подпиской и повторяющимися verification failures.

## FAQ

### FlowPilot помогает с бесплатной регистрацией GPT или Codex

Он может помочь пройти registration и authorization flow. Но доступность free registration зависит от текущих правил платформы. Лучше понимать этот термин как создание аккаунта, а не как обещание бесплатного долгосрочного доступа.

### HeroSMS гарантирует OpenAI verification

Нет. HeroSMS предоставляет номер и получение SMS. Успех зависит от платформы, страны номера, stock, IP и поведения регистрации.

### Что настраивать сначала: proxy или mailbox

Сначала gateway и mailbox. Proxy может улучшить стабильность, но он не исправит неправильный Temp API, неверный URL админки или пустой баланс SMS.

### Можно сразу включать Auto

Нет. Сначала один ручной проход. Auto нужен для повторения уже проверенного процесса.

### GPT и Codex аккаунты можно держать вместе

Можно хранить их в одной системе, но лучше разделять группами. GPT, Codex, Kiro и API relay ломаются по разным причинам.
